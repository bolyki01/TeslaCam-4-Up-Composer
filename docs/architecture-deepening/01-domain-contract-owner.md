# Domain Contract Owner

Goal: make app and CLI domain behavior change in one place, with fixture proof.

Read first:
- `docs/domain-contract.md`
- `fixtures/domain/cases/*.json`
- `TeslaCam/Indexer.swift`
- `TeslaCam/Models.swift`
- `TeslaCamTests/TeslaCamTests.swift`
- `teslacam_cli/scanner.py`
- `teslacam_cli/layouts.py`
- `teslacam_cli/domain_contract.py`
- `tests/test_domain_contract.py`

Problem:
- The scan contract is fixture-backed, but layout, selection, output naming, and dry-run are not equally owned.
- Swift and Python each encode camera vocabulary and layout decisions.
- The contract Interface is partly a doc, partly test helpers, partly duplicated Implementation.

Target shape:
- A deep Contract Module owns camera vocabulary, timestamp rules, duplicate policy, layout selection, selection math, output conflict naming, and manifest shape.
- Swift and Python remain separate Implementations.
- Fixtures are the Interface. Callers learn the fixture schema, not internal rules.

Steps:
1. Extend fixture schema with `expected_layout`, `expected_selection`, and `expected_output`. **Done.** All three sub-blocks land for every fixture: `expected_layout` covers `auto`/`legacy4`/`sixcam`; `expected_selection` covers every duplicate policy and is regenerated by `script/regen_selection_fixtures.py` using a stub `MediaProbe` (parity test `test_shared_selection_fixtures_round_trip_through_select_clip_sets_for_all_duplicate_policies`); `expected_output` records the default filename per mode plus the `unique`/`overwrite`/`error` policy resolutions and is regenerated by `script/regen_output_fixtures.py` (parity test `test_shared_output_fixtures_match_apply_output_conflict_policy_for_all_policies`). The two regen scripts share the same stub probe.
2. Add a Swift manifest builder for the same dry-run fields Python emits. **Mostly done** — `domainScanManifest(relativeTo:)` and `domainLayoutManifest` exist on the Swift side and produce JSON-equivalent shapes. A combined `domainDryRunManifest` aggregating scan + selection + layout + dimensions + encoder is still TODO; deferred until step 1's `expected_selection`/`expected_output` fixture fields land.
3. Add Swift tests that compare all fixture fields, not only scan fields. **Done.** Four parity tests cover every fixture × every policy: `sharedDomainFixturesMatchNativeScanManifestsForAllDuplicatePolicies` (scan), `sharedLayoutFixturesMatchNativeLayoutPlan` (layout / auto / legacy4 / sixcam), `sharedSelectionFixturesMatchNativeSelectionManifestForAllDuplicatePolicies` (selection — uses `[ClipSet].domainSelectionManifest(...)` with `clipDurationSeconds = 60`), and `sharedOutputFixturesMatchNativeOutputContractForEveryPolicy` (output — exercises `DomainOutputContract.defaultOutputFilename` / `applyConflictPolicy` / the typed `OutputAlreadyExistsError` against `expected_output`).
4. Add Python tests for layout and output conflict against the same fixtures. **Done** — `tests/test_domain_contract.py` validates `build_camera_layout_plan` against the new `expected_layout` block for every fixture/profile and `default_output_filename` + `unique_output_path` against the contract format.
5. Move camera order and alias notes into one contract vocabulary section in `docs/domain-contract.md`. **Done** — single "Camera vocabulary" section is now the source of truth, and "Clip file discovery" + "Layout selection" reference it.
6. Keep fixture data small: malformed names, hidden paths, duplicates, mixed HW3/HW4, directory output, file output, conflict suffix. **Done.** The case set covers: classic 4-cam (`classic_4_camera`), HW3-camera duplicates (`duplicates_same_camera`), HW4 6-cam (`hw4_6_camera`), mixed HW3/HW4 (`mixed_hw3_hw4`), malformed/hidden/non-video noise (`sparse_malformed_hidden`), single timestamp / smallest non-degenerate (`single_clip`), only-front / missing cameras render as black (`only_front`), and HW4 partial coverage / second-event missing cameras (`hw4_partial`). Conflict-suffix is in `expected_output.unique_resolution`; directory-vs-file output is in code-level tests. New fixtures only need `name` / `description` / `schema_version` / `files` — `script/regen_fixtures.py` populates every `expected_*` block from the contract sources.

Tests:
- `python3 -m unittest tests.test_domain_contract`
- `python3 -m unittest discover tests`
- `script/test_native.sh` after native test expectations are repaired

Guardrails:
- Native export stays the shipping app path.
- CLI stays dependency-light.
- Do not move logic into `_legacy/`.
- Do not use fixtures as generated output; keep them hand-readable.
